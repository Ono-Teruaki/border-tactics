| 論点 | 決定 |
|---|---|

## メタ分析の履歴（`npm run meta`、126編成の総当たり×3マップ×2回、94,500戦）
結果ファイルは `sim/results/meta-*.md`。

### v0.7
- **防護兵が一強**だった。上限ルール内の上位20編成はすべて防護兵入りで、1位は SSDD（84%）。防護兵が0体だと40%、1体で59%
- 強さの原因は**スキル（カバーリング）**。スキルを外すと、上位はアタッカーとガンナーの混成（AGGR, AGSR, AAGG）に入れ替わる。能力値を下げても（HP26／守14）、1手に庇える数を1発に制限しても、上位は防護兵入りのまま
- 「防護兵＋衛生兵＋G/A」の固めは平均60%で強いが、最強ではない。最強の組み合わせは「防護兵＋スナイパー」（70%）
- 衛生兵は弱い（1体で47%）。回復量を10にしてもほぼ変わらない
- この時点のCPUはマークを活かしていなかったので、スカウトのスキルの強さは判定できなかった

### v0.11 擲弾兵（試験中、`sim/results/meta-v0110-grenadier-unique.md`）
- 擲弾兵 X: HP20 攻12 守7 速12 命中70 減衰5 移動2 射程4 視界3 コスト2、懐−30
  - 曲射: 射線上のビル・遮蔽・張り付きの制限を受けない（見えている必要はある＝味方の視界で撃てる）
  - 爆風: 命中したら、狙った敵の上下左右の敵にも60%。爆発は防護兵が庇えない
- CPU: 爆風の見込みを狙いの価値に足す。爆風持ちの敵がいれば、上下左右に味方がいるマスを避ける（spread、既定1）

- CPUを散らせても（spread 0〜3）勝ち点率は変わらない（±2pt）。擲弾兵込みで調整し直した CPU は v0.10.2 に 46.3% で、v0.10.2 を基準に据え置き

### 先読みする CPU（v0.11.3、`src/engine/search.ts`）
- これまでの CPU は「相手はその場に留まる」前提の1手読み（ヒューリスティック）。対人では読みが浅く、最強編成でも勝てた
- 先読み: ヒューリスティック CPU の重みを揺らして自分の手の候補を作り、相手の応手もいくつか予想して、1〜2手を実際にシミュレーションし、撃破コストと残りHPで評価して手を選ぶ（平均と最悪を 7:3 で混ぜる）
- 見えていない敵は最後に見た位置にいる前提。相手はこちらの位置を知っている前提（悲観的）
- 調整済み CPU（strong）との対戦（ランダム編成・3マップ・先後入れ替え、各180戦）

| 設定（候補 / 応手 / 乱数の振り直し / 深さ） | 勝ち点率 | 1手の時間 |
|---|---|---|
| 6 / 3 / 2 / 1手 | 67.2% | 24ms |
| 6 / 3 / 2 / 2手 | 69.2〜72.5% | 46〜69ms |
| 10 / 4 / 3 / 2手（**ゲームの相手に採用**） | 74.7% | 164ms |
| 16 / 5 / 3 / 2手 | 76.9% | 270ms |

- 最悪の結果の重み（0 / 0.3 / 0.7）は誤差の範囲

### v0.11.2 レーダー塔（v0.11.3 で既定オフ、`sim/results/meta-v0112-radar-unique.md`）
- 実際に遊んで不要と判断したので、v0.11.3 から `rules.radar: false`（コードとマップの位置は残す）
- マップの特別なビル（アンテナ付き）。手の終わりに上にいると、次の手は敵全員が見える（撃てる相手も増える）。`rules.radar` で切替、`rules.radarMark` で見えた敵にマークも付ける（既定オフ）
- 今のマップ3枚とも、左上 (1,1) と右下の角に点対称で2本。どちらの出撃地点からも同じ距離
- CPU: 塔に一番近い味方1体が向かう（`radar`、既定1）。塔ごとに1体ずつ送ると、2体が団塊を離れて弱くなる
- 70編成のメタ: 1位 SRXD 65.6%（塔なし 71.1%）。上位4つが65%台で並ぶ
- ただし、塔を取りに行く CPU は、行かない CPU に勝てない。置き場所を変えても同じ（行く側の勝ち点率、各900戦）

| 置き場所 | 行く(1) 対 行かない(0) | 強く行く(2) 対 行かない(0) | SRXD 団塊あり 対 なし |
|---|---|---|---|
| 角（今） | 43.8% | 39.9% | 72.2% |
| 中央寄りの左右 | 42.0% | 32.7% | 73.3% |
| 自陣寄り（各陣に1本） | 45.9% | 37.7% | 76.2% |
| 中央に1本 | 38.4% | 24.2% | 79.6% |

- 角の塔は、初めて確保できるのが平均7手目、確保できる試合は5割強。レーダー中の撃破は1試合0.16体だけ
- 位置が分かっても、待っている相手には撃てる距離まで近づかないと得がない。今の CPU は「相手はその場に留まる」前提の1手読みなので、情報を攻めに変えられていない可能性もある

### v0.11.1 ジャマーの妨害にスキル無効化（`sim/results/meta-v0111-jam-silence-unique.md`）
- 妨害された敵は、その手と次の手、パッシブスキルが使えない（`skills.jamSilence`）。登ったその手の交戦から効く
  - 外れるもの: 追撃・観測・透視・制圧射撃・狙撃態勢・応急手当・カバーリング・後送・隠密・妨害・曲射・爆風
  - 残るもの: 懐の弱さ、スナイパーの移動制限
- CPU: 防護兵・衛生兵を妨害できる登りの価値を上げる。妨害された支援役は支援の価値を0とみなす
- 1位 SRXD 76.3% → 71.1%。ジャマーの入れ得度 −5.0 → +1.0、防護兵 +7.2 → +2.2。2位に GSJD、防護兵なしの SRJX が5位

### 団塊は擲弾兵で崩れるか（v0.11）

### 衛生兵の位置取り（`sim/results/medic.md`）
回復が少ないのは CPU の動かし方のせいか、ルールのせいかを切り分けた。

| | 今のCPU | 撃たずにいつも支援 |
|---|---|---|
| 回復した手 | 11.2% | 17.4% |
| けが人がいない手 | 51.7% | 56.7% |
| 撃つ手にした | 21.9% | 0% |
| 届いたのに外れた | 4.0% | 11.7% |
| 1体・1試合の回復量 | 5.4 | 7.8 |
| 最善の位置なら回復できた量（上限） | 14.7 | 13.5 |
| 衛生兵入り編成の勝ち点率 | 39.6% | 39.0% |

- CPUの取りこぼしはある。上限14.7に対して実際は5.4（37%）。一番の原因は「けが人がいるのに撃つ手にした」（上限のうち7.2）。CPUは回復を手の初めのHPで見積もるので、その手の交戦で味方が受ける傷を数に入れていない
- 味方の移動前の位置を基準に動く問題（衛生兵が後で決める `healerLast`）は小さい（5.4 → 5.6）
- ただし**上限そのものが低い**。最善の位置取りでも1試合14.7で、攻撃役の貢献（23〜29）の半分。半分以上の手で「回復できるけが人がいない」。ダメージが大きく、傷ついた味方がすぐ撃破されるため
- 撃たずに支援に徹すると回復は増えるが（5.4 → 7.8）、衛生兵自身の攻撃（1試合3.4）を失って勝ち点率は変わらない
- → **主な原因はルール**（回復は交戦の後で、致命傷には間に合わない）。CPUの改善だけでは攻撃役並みにならない

### 衛生兵・防護兵の細部
- 衛生兵は自分自身を回復しない。撃破された味方は対象外
- 防護兵: 命中判定は元の対象に対して行う（遮蔽などはそのまま）。防護兵が撃破されたら、それ以降の弾は元の対象に当たる。防護兵自身が狙われた場合は通常どおり受ける
- 未決: 回復量を固定値にするか最大HPの割合にするか。複数の衛生兵の回復を重ねるか

### 視界：構造物の奥
| 案 | 内容 | 判断 |
|---|---|---|
| A. 完全遮断 | 屋上からでも、途中にビルがあれば見えない | 屋上の価値が下がるので不採用 |

| C. 高さ比例 | 視点とビルの高さから影の長さを計算する | 盤が小さく効果の割に複雑なので不採用 |
